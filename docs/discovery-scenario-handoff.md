# 상황 파악에서 시나리오 생성까지 — 담당자 전달

## 범위

활성 공개 API `/api/trainings`의 상황 파악(TRN-04)과 생성(TRN-06), AI-01·AI-03만 개선했다. 역할극·리포트 및 FE 코드는 수정하지 않았다.

## 공통 코드

채용 사기는 `JOB_SCAM`이다. 기존 훈련 코드도 유지한다. 이 값은 AI의 세부 유형 `채용·아르바이트 사기`에 대응하며 `riskType`의 기존 기타 분류는 바꾸지 않는다.
AI 생성 결과의 `scenario.fraudTypeCode`를 Spring 세션과 공개 생성 응답에 반영한다. 따라서 중고거래로 고정되지 않는다.

## 상황 사실과 가상 설정

`facts.extractedFacts[]`의 기본 필드는 유지하고 내부 누적용 `factId`, `sourceTurn`을 추가한다. `facts.intakeTurn`은 대화 기록을 요약해도 입력 차수를 유지한다.
새 사실과 정정 사항은 누적하되 기존 전체 사실을 덮어쓰지 않는다. `scenario.sourceFacts`에는 가려진 사용자 사실을 전달하며 등장인물·첫 대사·장면은 가상 설정이다.
기관명을 말했다는 이유로 실제 안내를 사기라고 판단하지 않는다. 사용자가 말한 기관만 재사용한다.

## 준비 완료

공개 TRN-04 및 TRN-03의 `canGenerateScenario`가 생성 가능 여부의 기준이다. 답변 횟수는 표시용이며 5회만으로 준비 완료가 되지 않는다.
정보가 없으면 추가 입력을 받을 수 있고 구체적인 활동·경로가 이미 있으면 일찍 생성할 수 있다. Spring은 최근 상황 대화 20개와 누적 사실을 AI에 전달한다.

## FE 담당자에게 필요한 연결

새 메시지 응답에서는 이미 `canGenerateScenario`를 사용한다. 이어하기 복원도 TRN-03의 같은 필드를 사용해야 한다.
현재 FE는 복원 때 사용자 메시지가 하나라도 있으면 생성 버튼을 켜므로 정보가 부족한 상태에서도 버튼이 나올 수 있다. 다음과 같이 응답 필드를 기준으로 수정해야 한다.

```ts
// TrainingDetail에 canGenerateScenario?: boolean 추가
setCanGenerate(d.phase === "DISCOVERY" && d.canGenerateScenario === true)
```

기관별 GUIDE 자료나 화면 유형 이름에 새 코드를 표시하는 부분은 각 담당자에게 `JOB_SCAM`을 공유한다. 이번에 검토되지 않은 안내 자료를 새로 게시하지는 않았다.

## 검증

- 채용·거래·택배 입력에 맞는 분류와 기본 시나리오 생성
- 사실 중복·명시적 정정과 출처 차수 유지
- 정보 없음·거절·잘못된 AI 응답에서 생성 준비 완료 방지
- 기본 질문 반복 및 사용자가 말하지 않은 기관명 추가 방지
- 실제 Spring HTTP → FastAPI → OpenAI 상황 입력·생성 및 백엔드 결과 검증
