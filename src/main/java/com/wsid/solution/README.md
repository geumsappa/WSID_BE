# solution — 실제 피해 대응

사용자가 '사기가 의심돼요 / 피해를 당했어요'를 누른 뒤의 흐름을 맡아요.
틀리면 실제 피해로 이어지는 부분이라, **카드 선택과 긴급 여부는 코드 규칙으로만 정해요.**

|---|---|---|---|---|

## 이용 정책과 목표 API

피해 대응 AI 상담은 비회원도 이용할 수 있어요. 아래 SOL API의 로그인 요구는 최신 사용자 결정에 따라 불필요로 정정했어요. 비회원 상담도 복원·변경·종료 시 해당 상담의 소유권을 확인해야 해요.

| API ID | 메서드 | 경로 | 인증 | 현재 구현 |
|---|---|---|---|---|
| SOL-01 | POST | `/api/solutions/sessions` | 불필요 (비회원 상담 소유권 확인 필요) | SolutionSession.start만; 시작 설명 즉시 추출 없음 |
| SOL-02 | GET | `/api/solutions/sessions/{id}` | 불필요 (비회원 상담 소유권 확인 필요) | 엔티티·소유자 조건 repository만; 서비스·API 없음 |
| SOL-03 | POST | `/api/solutions/sessions/{id}/messages` | 불필요 (비회원 상담 소유권 확인 필요) | 메시지 엔티티만; 서비스·API 없음 |
| SOL-04 | PATCH | `/api/solutions/sessions/{id}/facts` | 불필요 (비회원 상담 소유권 확인 필요) | factsJson 컬럼만; 병합·재판정·API 없음 |
| SOL-05 | POST | `/api/solutions/sessions/{id}/complete` | 불필요 (비회원 상담 소유권 확인 필요) | completedAt 컬럼만; 종료 메서드·API 없음 |

현재는 `solution_sessions.user_id NOT NULL` 및 users 외래키, `CurrentUser` 기반 계정 식별 구조만 있어 비회원 상담을 처리할 수 없어요. 비회원 소유자 식별 방법·저장 구조·복원 범위를 설계하고 새 마이그레이션으로 지원해야 해요. 구체적인 쿠키·식별자 계약은 아직 확정하지 않았어요. 상담 ID만 받아 타인 상담을 조회하게 만들지 않아요.

## 테이블

- `solution_sessions`: 확인한 사실, 적용된 카드, 다음 질문 → `domain/SolutionSession`
- `solution_messages`: 대화 한 줄. `safe_content`에는 민감정보를 가린 내용만 저장 → `domain/SolutionMessage`

## 개발 순서

training 패키지와 같은 모양으로 만들어요.

1. **domain 규칙부터**: 사실을 값 객체로 만들어요. 항목은 송금, 정보 제공, 앱 설치, 연락 지속이고 값은 예·아니오·모름이에요.
   `SolutionSession`에 `mergeFacts(...)`(바꾼 항목만 갱신)를 추가하고, `ResponseRules`(사실 → 카드 코드 목록, 긴급 여부, 다음 질문)를 순수 Java로 만들어요.
2. **단위 테스트**: "보냈다", "보내려다 멈췄다", "송금을 언급하지 않았다"가 구분되는지, 긴급 카드가 맨 앞에 오는지, 모름일 때 더 안전한 쪽 안내가 나오는지 검증해요.
3. **AI 연결**: `AiClient`에 사실 추출(I5) 메서드를 추가해요. 실패하면 화면에서 직접 선택하게 해요. 선택으로 확인한 사실도 같은 규칙에 넣어요.
4. **service**: 상담 소유자 확인 → 읽기 → AI 호출(트랜잭션 밖) → 사실 합치기 → 규칙 적용 → 저장. 시작 요청에 설명이 있으면 바로 AI-06으로 사실을 추출해요. `content`에서 카드 내용을 가져와 응답을 만들어요.
5. **controller**: SOL-01~05의 시작·복원·메시지·사실 수정·완료를 구현해요. 비회원 소유권을 유지하며, 완료 상태와 완료 후 허용 요청·응답은 계약으로 정의해요.
6. **근거 검색(I6)**: 긴급 카드가 없을 때만 호출해요. 긴급 카드는 검색을 기다리지 않아요.

## 규칙

- 기관명, 연락처, 링크는 `content`의 검토된 카드에서만 가져와요. AI가 만든 값은 쓰지 않아요.
- 피해 설명 원문과 추출 근거는 DB와 로그에 남기지 않아요.
- 확인하지 못한 항목은 '모름'으로 유지해요. 추측해서 '아니오'로 바꾸지 않아요.
- 지난 질문의 선택지는 다시 적용하지 않아요. `next_question_json`과 요청의 질문 ID가 다르면 최신 상태를 다시 불러오게 해요.

## 정할 것

- 비회원 상담 소유자 식별·저장·만료·복원 방식 (로그인 불필요 정책은 확정)
- 훈련 중 실제 피해를 밝혔을 때 어느 훈련에서 넘어왔는지 연결할 컬럼
- 근거 문단의 화면 표시 여부와 공개 API 필드
